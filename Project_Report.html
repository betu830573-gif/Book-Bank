1. Problem Statement

In college institutions, standard textbooks representing syllabus frameworks are extremely expensive, costing students significant funds each semester. To equalize access to learning materials, colleges establish a Book Bank sub-facility. Here, students borrow textbook sets for the semester and return them post-exams.

Legacy System Inefficiencies:

  • Manual Overhead: Paper ledger entries lead to sluggish search operations, book tracking delays, and long queues.
  • Lack of Transparency: Students are unaware of stock availability or outstanding fines until they physically check with library staff.
  • Human Error: Manual calculations of overdue dates frequently lead to clerical errors and disputes over fine balances.
  • No Personalization: Students must browse through bookshelves without digital guidance regarding which textbooks match their registered engineering branches.

2. Software Requirements Specification (SRS)

This SRS complies with the IEEE 830 standard parameters to define the operational functions of the Book Bank Management System.

2.1 Scope & Purpose

The Book Bank Management System (BBMS) provides a responsive digital gateway for college student exchanges. It automates catalog searching, stock-level tracking, checkout approvals, return processing, and automated fine accounting, using client-side algorithms to deliver tailored book recommendation paths.

2.2 Functional Requirements (FRs)

  • FR-1: Authentication: Dual logins separating Student and Admin roles securely. New students can register using their IDs and branches.
  • FR-2: Dynamic Catalog Search: Real-time filtering of textbooks by Title, Author, ISBN, or Department/Branch.
  • FR-3: Reservation Requests: Students submit reservation requests directly from their dashboards, decrementing stock automatically upon Admin approval.
  • FR-4: Active Fine Engine: Automatically calculates overdue fees ($1.00 per day) based on a 14-day return policy. Allows simulated online clearance.
  • FR-5: AI recommendation Engine: Maps curriculum syllabus requirements using content-based logic to prioritize branch textbooks first, augmented by peer demand frequencies.

2.3 Non-Functional Requirements (NFRs)

  • NFR-1: Reliability: Integrates synchronized localStorage systems to preserve user states across reloads.
  • NFR-2: Usability: Responsive and lightweight layout leveraging modern Bootstrap 5 components.
  • NFR-3: Security: Dual dashboard segregation restricting direct unauthorized page traversal.

Defines the database entity structures and primary/foreign key connections:

  • Student Entity: student_id (PK), name, email, password, department, balance_due.
  • Book Entity: isbn (PK), title, author, department, total_quantity, available_quantity, cover_url.
  • Circulation Entity: record_id (PK), student_id (FK), isbn (FK), issue_date, due_date, return_date, fine_applied, status.

Relationship: Students can check out multiple books over time (1-to-Many), and books can appear in multiple circulation records (1-to-Many).

4.2 White Box Testing (Logical Path Analysis)

We analyze the AI Recommendations Engine pathing logic (`ai.js`) using branch coverage parameters:

  • Path A (Null History): Student is newly registered and has no checkout history.
    -> Result: System returns general trending academic books matching the student's department.
  • Path B (Active History): Student has checked out textbooks in the past.
    -> Result: System scores all books by analyzing matching department weights (+50 pts) and previous category checkouts (+10 pts per match) to present custom lists.

5. Production Database Schema

Here is the standard SQL script detail used to initialize the physical database infrastructure:

-- Relational Tables creation script
CREATE TABLE students (
    student_id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    department VARCHAR(100) NOT NULL,
    balance_due DECIMAL(10, 2) DEFAULT 0.00
);

CREATE TABLE books (
    isbn VARCHAR(50) PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255) NOT NULL,
    department VARCHAR(100) NOT NULL,
    total_quantity INT NOT NULL,
    available_quantity INT NOT NULL
);

CREATE TABLE circulation_records (
    record_id VARCHAR(50) PRIMARY KEY,
    student_id VARCHAR(50) REFERENCES students(student_id),
    isbn VARCHAR(50) REFERENCES books(isbn),
    issue_date DATE,
    due_date DATE,
    return_date DATE NULL,
    fine_applied DECIMAL(10, 2) DEFAULT 0.00,
    status VARCHAR(50) DEFAULT 'Issued'
);
